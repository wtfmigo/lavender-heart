# Full-page visual recomposition implementation plan

The latest brief authorizes recomposing the nine existing public chapters and asks for a visual-review stop only after the finished deliverables. The existing isolated feature worktree and approved contracts/history remain. No backend, admin, upload, authentication or recovery work is included.

**Design:** Preserve the original cloudy Hero, fonts and palette. Replace repeated collage rhythm with viewport-scale chapter introductions, six distinct Story spreads, a portrait-led masonry Gallery, large date-led Timeline, quiet ivory Letter and a dominant dark Finale. Keep one live Canvas with explicit per-section states and restrained static heart echoes in chapter introductions so the motif remains visible in full-page composition as well as actual scrolling. Missing actual dates remain null; optional presentation labels in isolated development content show YOUR YEAR / YOUR DATE rather than fabricated years.

**Alternatives considered:** CSS-only resizing would retain the repeated structure; adding chapters or a new rendering system would exceed scope. Recompose existing components and their data, with scoped GSAP changes, to fix the supplied composition problems directly.

**Files:** Existing `StoryChapters.tsx`, `Gallery.tsx`, chapter/gallery/journey styles, `useJourneyAnimation.ts`, local `experience.json`, public presentation types/schema; new small `ChapterScene.tsx` and its styles if shared headings need reuse. Media preparation/provenance and before/after QA scripts/evidence. Existing callers/tests update where selectors or visual behavior change. No new dependencies or domain/database changes.
